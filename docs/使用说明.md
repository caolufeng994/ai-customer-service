## 环境要求

### 必需环境

| 组件 | 版本要求 | 用途 |
|------|---------|------|
| **Python** | 3.9+ | 后端运行环境 |
| **Node.js** | 16+ | 前端运行环境 |
| **MySQL** | 8.0+ | 关系型数据库 |
| **pip** | 最新版 | Python包管理器 |
| **npm** | 8.0+ | Node包管理器 |

| 组件 | 版本要求 | 用途 |
|------|---------|------|
| **DashScope API Key** | - | 阿里云通义千问（主LLM） |

- **CPU**: 4核以上推荐

## 快速开始

### 前置检查

在开始之前，请确保已安装以下工具：

```bash
# 检查 Python 版本
python --version  # 应显示 3.9 或更高

# 检查 Node.js 版本
node --version    # 应显示 16 或更高

# 检查 MySQL 服务
mysql --version   # 应显示 MySQL 8.0 或更高
```

### 一键启动（推荐）

如果您已配置好所有环境，可以按以下顺序快速启动：

```bash
# 1. 启动 MySQL 服务
# Windows: 在服务管理器中启动 MySQL80 服务
# Linux/Mac: sudo systemctl start mysql

# 2. 初始化数据库
mysql -u root -p < database/init_db.sql

# 3. 启动后端
cd backend
pip install -r requirements.txt
cp .env.example .env  # 编辑 .env 填入配置
python -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000

# 4. 启动前端（新终端）
cd frontend
npm install
npm run dev
```

启动完成后，访问 http://localhost:5173 即可使用系统。

## 详细配置

### 1. 数据库配置

#### 安装 MySQL

**Windows:**
1. 下载 MySQL Installer: https://dev.mysql.com/downloads/installer/
2. 运行安装程序，选择 "Developer Default"
3. 设置 root 密码（请记住此密码）
4. 完成安装后启动 MySQL 服务

**Linux (Ubuntu/Debian):**
```bash
sudo apt update
sudo apt install mysql-server
sudo systemctl start mysql
sudo mysql_secure_installation
```

**macOS:**
```bash
brew install mysql
brew services start mysql
```

#### 初始化数据库

```bash
# 登录 MySQL
mysql -u root -p

# 执行初始化脚本
source database/init_db.sql

# 或直接从命令行执行
mysql -u root -p < database/init_db.sql
```

验证数据库创建成功：
```sql
USE ai_customer_service;
SHOW TABLES;
-- 应显示 8 张表：users, sessions, messages, kb_documents, kb_chunks, message_citations, feedback, usage_quota
```

### 2. 后端配置

#### 安装 Python 依赖

```bash
cd backend

# 创建虚拟环境（推荐）
python -m venv venv

# 激活虚拟环境
# Windows:
venv\Scripts\activate
# Linux/Mac:
source venv/bin/activate

# 安装依赖
pip install -r requirements.txt
```

#### 配置环境变量

```bash
# 复制示例配置文件
cp .env.example .env

# 编辑 .env 文件，填入实际配置
```

**.env 配置说明：**

```bash
# 数据库配置
DATABASE_URL=mysql+pymysql://root:your_password@localhost:3306/ai_customer_service

# JWT 配置
JWT_SECRET_KEY=your-secret-key-change-this
JWT_ALGORITHM=HS256
JWT_EXPIRE_HOURS=24

# LLM 配置（DashScope - 阿里云通义千问）
DASHSCOPE_API_KEY=your-dashscope-api-key
DASHSCOPE_MODEL=qwen-turbo

# LLM 配置（Ollama - 本地降级备选）
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_MODEL=qwen2

# Embedding 配置
EMBEDDING_MODEL=text-embedding-v2
EMBEDDING_PROVIDER=dashscope  # 或 local

# Chroma 向量数据库配置
CHROMA_PERSIST_DIR=./chroma_db

# 文件上传配置
MAX_UPLOAD_SIZE=10485760  # 10MB

# RAG 配置
CHUNK_SIZE=500
CHUNK_OVERLAP=80
RETRIEVER_TOP_K=8
RETRIEVER_SIMILARITY_THRESHOLD=0.6
CONTEXT_MAX_TOKENS=2000

# 业务规则配置
MESSAGE_MAX_LENGTH=500
DAILY_QUOTA_LIMIT=100
```

**获取 DashScope API Key:**
1. 访问阿里云百炼平台: https://bailian.console.aliyun.com/
2. 注册/登录账号
3. 创建 API-KEY
4. 复制到 `.env` 文件

**安装 Ollama（可选，用于降级）:**
```bash
# Linux/Mac
curl -fsSL https://ollama.com/install.sh | sh

# Windows (WSL)
# 同上命令

# 拉取模型
ollama pull qwen2
```

### 3. 前端配置

#### 安装 Node 依赖

```bash
cd frontend

# 安装依赖
npm install

# 如果安装失败，可尝试使用淘宝镜像

```

## 运行流程

### 用户使用流程

#### 1. 用户注册/登录

```
访问系统 → 点击注册 → 填写用户信息 → 提交 → 自动登录
```

#### 2. 知识库管理（可选）

```
登录后 → 点击知识库 → 上传文档 → 等待处理 → 文档向量化完成
```

支持的文档格式：
- `.txt` - 纯文本
- `.md` - Markdown
- `.pdf` - PDF文档

#### 3. 智能问答

```
选择对话 → 输入问题 → 点击发送 → 系统检索 → LLM生成 → 流式返回答案
```

**RAG 处理流程：**
1. 用户输入问题
2. 系统将问题向量化
3. 从向量库检索相关文档片段
4. 构建上下文和提示词
5. 调用 LLM 生成答案
6. 流式返回答案给用户
7. 保存对话记录和引用来源

#### 4. 多轮对话

```
在同一对话中继续提问 → 系统结合历史对话 → 生成连贯回答
```

系统会保留最近 5 轮对话历史，确保上下文连贯。

#### 5. 反馈评价

```
对AI回答进行评价 → 点赞/点踩 → 可选填写评论 → 提交反馈
```

### 系统内部流程

#### 文档上传流程

```
1. 前端上传文件 → 后端接收
2. 文件类型检测 → 选择对应加载器
3. 文本提取 → 中文递归分块
4. 批量向量化 → 存入 Chroma
5. MySQL 记录元数据
6. 返回上传结果
```

#### 聊天请求流程

```
1. 前端发起 SSE 请求
2. 后端验证 JWT Token
3. 检查用户配额
4. 获取/创建会话
5. 保存用户消息
6. RAG 检索 → 构建 Prompt
7. 调用 LLM（主模型或降级）
8. 流式返回答案
9. 保存助手消息和引用
10. 更新配额
11. 结束 SSE 流
```

#### LLM 降级流程

```
主 LLM 调用 → 异常？
  ├─ 否 → 正常返回
  └─ 是 → 切换 Ollama → 重新生成 → 返回答案
```

降级触发条件：
- 网络超时
- API 限流
- API Key 失效
- 服务不可用

## 常见问题

### Q1: MySQL 连接失败

**错误信息：** `Can't connect to MySQL server on 'localhost'`

**解决方案：**
1. 检查 MySQL 服务是否启动
2. 检查 `.env` 中的数据库配置是否正确
3. 检查防火墙是否阻止了 3306 端口

```bash
# 检查 MySQL 服务状态
# Windows: services.msc 查看 MySQL80
# Linux: sudo systemctl status mysql
# macOS: brew services list
```

### Q2: 后端启动失败 - 依赖安装错误

**错误信息：** `ModuleNotFoundError: No module named 'xxx'`

**解决方案：**
```bash
cd backend
pip install -r requirements.txt --upgrade
```

如果某些包安装失败，尝试：
```bash
pip install --upgrade pip
pip install -r requirements.txt --no-cache-dir
```

### Q3: 前端启动失败 - 依赖安装错误

**错误信息：** `npm ERR! code ERESOLVE`

**解决方案：**
```bash
cd frontend
rm -rf node_modules package-lock.json
npm install --legacy-peer-deps
```

或使用淘宝镜像：
```bash
npm install --registry=https://registry.npmmirror.com
```

### Q4: LLM 调用失败

**错误信息：** `DashScope API Error` 或 `Authentication failed`

**解决方案：**
1. 检查 `.env` 中的 `DASHSCOPE_API_KEY` 是否正确
2. 检查 API Key 是否有余额
3. 检查网络连接是否正常
4. 如果主模型失败，系统会自动降级到 Ollama（需提前安装）

### Q5: 向量检索无结果

**可能原因：**
- 知识库未上传文档
- 相似度阈值设置过高
- 问题与文档内容不相关

**解决方案：**
1. 先上传一些知识文档
2. 检查 `.env` 中的 `RETRIEVER_SIMILARITY_THRESHOLD`（默认 0.6）
3. 系统会自动降级阈值到 0.3 进行二次检索

### Q6: SSE 流式响应中断

**可能原因：**
- 前端网络断开
- 后端服务重启
- LLM 超时

**解决方案：**
1. 检查网络连接
2. 查看后端日志确认错误
3. 重新发送问题

### Q7: 前端无法连接后端

**错误信息：** `Network Error` 或 `ERR_CONNECTION_REFUSED`

**解决方案：**
1. 确认后端已启动在 8000 端口
2. 检查 `vite.config.ts` 中的代理配置
3. 检查浏览器 CORS 设置
4. 尝试直接访问 http://localhost:8000/docs 验证后端

### Q8: 配额超限错误

**错误信息：** `Daily quota exceeded (100 questions per day)`

**解决方案：**
1. 等待第二天配额重置
2. 或修改 `.env` 中的 `DAILY_QUOTA_LIMIT`
3. 或直接修改数据库中的 `usage_quota` 表

### Q9: 文件上传失败

**错误信息：** `File too large` 或 `Unsupported file type`

**解决方案：**
1. 检查文件大小是否超过 10MB
2. 确认文件格式为 `.txt`、`.md` 或 `.pdf`
3. 检查后端日志确认具体错误

### Q10: Chroma 向量数据库错误

**错误信息：** `ChromaError: ...`

**解决方案：**
```bash
cd backend
# 删除现有向量数据库
rm -rf chroma_db

# 重新上传文档会自动重建
```
