# 代码规范

本文档定义 AI 智能客服系统的代码编写与提交规范，所有提交必须遵循。

## 1. 目录与分层约定

后端严格分层，禁止跨层调用：

```
api/      → 仅做 HTTP 参数校验与路由，不含业务逻辑
services/ → 业务逻辑（配额、会话、文档处理、RAG 编排）
rag/      → RAG 核心算法（langchain 风格独立组件）
core/     → 基础设施（异常、响应、日志）
models/   → SQLAlchemy ORM 模型
schemas/  → Pydantic 请求/响应模型
utils/    → 通用工具（鉴权、依赖注入）
```

- `api` 层调用 `services`，`services` 调用 `rag`/`models`，`rag` 不反向依赖 `api`/`services`。
- 前端：`pages/`（页面）、`utils/`（请求封装等），组件按路由划分。

## 2. Python 编码规范

- **命名**：函数/变量 `snake_case`，类 `PascalCase`，常量 `UPPER_CASE`，模块名全小写。
- **类型注解**：所有函数签名必须带类型注解（`def foo(x: int) -> str`）。
- **文档字符串**：每个公开类/方法必须有 docstring，说明用途、参数、返回值；`rag/` 核心模块额外写清设计要点与算法选择。
- **模块级 docstring**：每个 `.py` 文件首行写模块职责（参考现有 `llm_client.py` 风格）。
- **ORM**：统一用 SQLAlchemy 2.0 风格（`Mapped[...]` / `select()`），除 `init_db.sql` 外禁止裸 SQL。
- **数据库**：所有外键字段必须建索引；枚举用 `Enum` 类型；`kb_chunks.vector_id` 是 MySQL↔Chroma 唯一桥梁，删除文档必须按它批量删向量。
- **日志**：统一 `logging.getLogger(__name__)`，按 DEBUG/INFO/WARNING/ERROR 分级，禁止 `print()` 调试。
- **异常处理**：抛出 `core.exceptions.BaseAppException` 子类，由 `exception_handlers` 统一转响应；禁止在 `api` 层裸 `raise` 普通 `Exception`。

## 3. 前端编码规范

- **TypeScript**：`tsconfig` 开启 `strict: true`，禁止 `any`（必要处用 `unknown` + 类型守卫）。
- **组件**：函数式组件 + Hooks；文件名与组件名 `PascalCase`；`interface` 定义 props/state。
- **UI 规范（重要）**：统一使用 Ant Design 组件与**默认样式**，**禁止大量自定义 CSS**，禁止为"好看"写大段 inline style（现有 `Sessions.tsx` 的 inline style 属于违反，需回归 AntD 默认）。
- **SSE 流式调用**：**必须使用 `fetch` + `ReadableStream` 手动解析**，禁止使用 `EventSource`（因需 POST + Authorization 头，EventSource 不支持）。请求统一走 `utils/request.ts` 拦截器（自动带 Token、统一错误提示）。
- **状态码**：401 清 Token 跳登录，429 提示配额超限，其余弹错误文案。

## 4. Git 与提交规范

> 当前仓库尚未 `git init`，首次提交前必须初始化并补齐以下约定。

- **分支模型**：`main`（受保护，不可直推）、`dev`（集成）、`feature/xxx`（按功能开分支）。
- **Commit 格式**：`<type>(<scope>): <subject>`
  - type：`feat` / `fix` / `docs` / `refactor` / `test` / `chore`
  - scope：模块名（如 `rag`、`chat`、`frontend`）
  - 例：`feat(rag): 增加空检索阈值降级`、`fix(chat): 修复 SSE 中断`
- **评审**：`feature` → `dev` 需 PR + 至少一次 self-review（对照下方 DoD）。
- **密钥**：`.env` 不入库；仅提交 `.env.example`。

## 5. 静态检查（待补齐配置）

- 前端：`eslint` 配置当前缺失，需新增 `.eslintrc.cjs`（含 `@typescript-eslint`、`react-hooks`、`react-refresh`），`npm run lint` 必须 0 warning。
- 后端：原 `ruff.toml` 已**移除**；**不引入 pre-commit / CI 强制 lint**，提交由手动 `git commit` 完成。本地可自选 `ruff check`（默认规则）/ `black` 自查，但非提交门禁。
- 格式化：统一用 `black`（后端）/ `prettier`（前端）。

## 6. 测试规范

- **Spike 先行**：涉及新外部依赖（LLM/Embedding/Chroma）必须先跑 `spike/` 验证连通性。
- **单元测试**：`services/` 与 `rag/` 核心方法需单测（mock 外部调用）。
- **评测集**：维护 25 条问答评测集（见《开发流程规范》），覆盖检索准确率 >80%、回答准确率 >75%、引用准确率 >90%。

## 7. 完成定义（DoD）

一个功能模块被认为"完成"，当且仅当：
1. 代码无类型错误（建议本地 `ruff check` / `black` 自查，非强制）；
2. 对应 API 在 `/docs` 可测通，响应符合《API 文档》；
3. 关键路径有日志；
4. 若涉及 RAG，已用评测集验证；
5. 相关文档（架构/API/数据库）已同步更新。
