# 文档索引（开发标准统一入口）

> **本文件是所有开发需求的唯一总入口。** 后续任何改动，都先经本索引定位规范、读完再动手，确保方向始终对齐项目标准。

---

## 〇、使用说明（操作协议）

**AI / 工程师收到新需求时的标准动作：**

1. **提取关键词**：从需求描述中拆出技术关键词（如"新增登录接口" → `API` + `鉴权` + `数据库`）。
2. **定位规范**：先查下方「三、检索指引（按需求类型）」，再查「四、关键词 → 文档映射」，得到该需求对应的**必读文档列表**。
3. **先读后写**：用 Read 工具打开这些文档，对齐命名 / 分层 / 提交 / 测试等约束，**未读规范不动代码**。
4. **开发 + 自检**：编码后对照《开发流程规范》§6「提交前 16 项检查清单」与《代码规范》§7「完成定义（DoD）」逐项核验。
5. **同步文档**：涉及接口 / 数据模型 / 架构的改动，同步更新对应文档（API 文档 / 数据库设计 / AI 架构设计）。

> 原则：**规范优先于直觉，索引优先于记忆。** 任何"我记得项目里是……"都应回到本索引指向的源文档确认。

## 一、文档分类体系

### 1. 代码规范（命名 / 格式 / 架构约定）
统一编码与提交标准，所有代码必须对齐。
- `docs/代码规范.md`（核心：分层、命名、类型注解、docstring、日志、异常处理、Git 提交、DoD）
- `docs/技术栈选型.md`（新增依赖 / 技术决策时的选型依据，参考级）

### 2. 开发流程规范（Git 工作流 / 分支策略 / Code Review）
定义协作节奏与质量门禁。
- `docs/开发流程规范.md`（里程碑、main/dev/feature 分支模型、CR、16 项检查清单、评测集）
- `NOTES.md`（根目录，知识沉淀：AI 改了什么、为何改、踩坑记录 — 流程强制要求）

### 3. 业务领域规范（Business Domain）
理解系统要解决什么业务问题。
- `docs/业务流程说明.md`（注册登录、知识库管理、智能问答、反馈等流程）
- `项目说明.md`（根目录，项目全貌、核心功能、技术栈总览 — 首读入口）

### 4. API 设计规范（API Design）
接口契约与代码层约定。
- `docs/API文档.md`（全部端点、请求/响应、错误码、业务规则 — 联调契约）
- `docs/代码规范.md` §1（api 层只做校验路由、不含业务逻辑的分层约定）

### 5. 测试规范（Testing）
测试与质量保障要求（项目暂无独立测试规范文档，由以下章节覆盖）。
- `docs/代码规范.md` §6（Spike 先行、单测、评测集要求）
- `docs/开发流程规范.md` §5（评测集与质量门禁）、§6（提交前检查清单）

### 6. 架构与技术参考（Reference）
实现细节、评审与查漏补缺。
- `docs/AI架构设计.md`（RAG 架构、模块职责、流水线、性能优化）
- `docs/数据库设计.md`（ER 图、8 张表结构、字段 / 索引 / 外键约束）
- `docs/架构设计评审与整改清单.md`（按层次的安全 / 数据 / RAG / API / 前端 / 工程化问题清单，含严重程度与修复方向）
- `docs/需求符合性检查报告.md`（逐条对照笔试题评分维度，核查已实现与待补）

### 7. 运行与部署（Ops）
本地运行与演示。
- `运行指南.md`（根目录，环境、启动、配置、部署、故障排查）
- `AI智能客服系统_执行方案.md`（根目录，总体规划与 5 天交付计划，参考级）
