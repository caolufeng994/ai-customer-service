## 三、已修复项详述（验收证据）

### S1 / S2 / S3 — 安全三项（P0，全部关闭）
- **问题**：密钥/密码有公开默认值、debug 默认开，生产易泄漏/越权。
- **整改**：`config.py` 将 `jwt_secret_key` 改为 `Field(..., min_length=32)`、`db_password` 改为 `Field(..., min_length=1)`、`debug` 默认 `False`。缺失密钥/密码时 Pydantic 启动即报错（fail-fast）。
- **验证**：`config.py:24,31,16`；`main.py:100` 的 `reload` 绑定 `settings.debug`。

### B3 — Embedding 失败不再静默（P1）
- **问题**：原实现返回零向量，导致上层误判"无相关内容"而不报障。
- **整改**：`embedder.embed_batch` 在 DashScope/本地调用异常时 `raise RuntimeError("Embedding service unavailable: ..)`。
- **验证**：`embedder.py:93`、`:108`。

### B4 / C1 — 配置单一来源（P1，已解决）
- **问题**：`retrieval_threshold=0.35` 与实际硬编码 `0.6` 不一致；`max_history_rounds` 未使用。
- **整改**：`get_retriever()` 改为读 `settings.retrieval_top_k` / `settings.retrieval_threshold`；历史截取 `limit = settings.max_history_rounds * 2`。
- **验证**：`chat_service.py:28`、`:93`。配置漂移消除。

### B9 — LLM/Embedding 超时与重试（P1）
- **整改**：DashScope 客户端 `timeout=30, max_retries=2`；Ollama `timeout=60, max_retries=2`；Embedder 同设。
- **验证**：`llm_client.py:32-33`、`:40-41`；`embedder.py:35-36`。

### A1 — SSE 优雅降级（P1）
- **整改**：`chat_stream` 主模型失败→fallback Ollama；Ollama 再失败→yield 友好文案"抱歉，服务暂时不可用，请稍后重试。"，流正常结束。
- **验证**：`chat_service.py:247-264`。

### A2 — 配额校验前移（P2）
- **整改**：`api/chat.py` 在进入 `StreamingResponse` 前调用 `check_quota`，超限返回标准 4xx，不再断流。
- **验证**：`api/chat.py:36-39`。

### A4 — 统一异常处理（P2）
- **整改**：`main.py` 注册 `BaseAppException` 与通用 `Exception` 全局处理器，统一错误结构。
- **验证**：`main.py:81-82`。

### F1 — 前端引用来源展示（P0，核心交付项）
- **整改**：助手消息卡片下方渲染 `sources`，展示「相关度: xx.x%」标签 + snippet 文本。
- **验证**：`Sessions.tsx:222-232`、`done` 事件已挂载 `sources`(`:142`)。

### F2 — 用户反馈入口（P1）
- **整改**：每条助手消息下「有帮助/无帮助」按钮，弹窗提交 `POST /api/feedback`。
- **验证**：`Sessions.tsx:83-104`、`:233-252`。

### D4 — 引用价值释放（➖）
- 随 F1 前端展示而自然解决，无需额外改动。

## 四、未整改项详述与后续措施

### 【P1 关键待办 — 建议优先】

**S4 · 全局限流/防刷（❌）**
- 现状：仅 `check_quota` 单用户每日 100 次；无 IP 级、无全局 RPS；批量注册可绕过。
- 措施：引入 `slowapi` 或 Redis 滑动窗口；关键写操作（上传/反馈）加风控。
- 验收：压测下单一 IP 超出阈值返回 429。

**S5 · Prompt Injection 防护（❌）**
- 现状：`prompt_builder.py:69` 用户 query 直接拼入 user message，无指令隔离。
- 措施：① system 与 user 内容分通道；② 对 query 做注入模式过滤；③ 输出约束"必须基于检索片段作答，否则拒答"。
- 验收：构造注入样本，验证模型不越界泄露系统指令。

**B1 · 意图识别（❌）**
- 现状：无意图分类/路由。
- 措施（二选一）：① 落地轻量意图分类（LLM function-calling 或 小模型）并写入 `intent_tag`；② 在 `AI架构设计.md` 明确声明"单意图 RAG 设计"并清理 D3 死字段。
- 验收：若选①，会话标题/标签可展示意图；若选②，文档声明 + 字段清理完成。

**B2 · 检索重排序（❌）**
- 现状：`retriever.py` 单阶段向量检索，规模增大后 Top-1 易被语义相近无关块挤占。
- 措施：召回 `top_k=20` → Reranker（`bge-reranker-v2-m3` 或 Cohere）重排取 `top_5`；可叠加 BM25 混合检索。
- 验收：评测集检索准确率提升（目标 >80%）。

**C3 · 核心 RAG 单元测试（❌）**
- 现状：`backend/tests/` 经核查不存在；仅外部集成测试 `test_api.py`。
- 措施：在 `backend/tests/` 加 pytest 单测，mock Embedder/VectorStore，覆盖阈值过滤、fallback、token 预算、多轮改写；CI 强制运行。
- 验收：`pytest` 通过且 CI 门禁生效。
