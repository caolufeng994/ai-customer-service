# 开发流程规范

本文档规定 AI 智能客服系统的开发流程、里程碑、提交前检查与知识沉淀机制。

## 1. 里程碑（五日计划）

| 里程碑 | 时间 | 交付物 | 状态 |
|--------|------|--------|------|
| M1 基建跑通 | Day 1 | spike 三连通过（LLM/Embedding/Chroma）+ DB 初始化 + 认证 | ✅ 代码已就绪，待联调 |
| M2 RAG 核心 | Day 2 | loader/splitter/embedder/vector_store/retriever 单测通过 | ✅ 已实现 |
| M3 业务闭环 | Day 3 | 知识库上传/删除 + 流式问答 + 配额 + 引用 | 🟡 后端完成，前端 SSE 未完成 |
| M4 加分题 | Day 4 | 大规模检索 LLM 保障方案 + Agent 任务拆解文档 | ⬜ 待启动 |
| M5 收尾提交 | Day 5 | 8 份文档齐 + 自测 + 23:59 前邮件发出 | ⬜ 待启动 |

> 红线：前端零自定义 CSS（用 AntD 默认）；SSE 必须 fetch+ReadableStream；响应头带 `X-Accel-Buffering: no`；`vector_id` 作为删向量唯一键。

## 2. 分支与提交

- 详见《代码规范》第 4 节：main/dev/feature 分支模型，Commit 格式 `type(scope): subject`。
- 每个 feature 分支合入 dev 前，对照第 6 节 DoD 自检。

## 3. 每日进度追踪

维护一份进度表（建议直接在《执行方案》末尾或本项目 README 更新），每日下班前更新：

```
| 日期 | 完成项 | 阻塞项 | 明日计划 |
|------|--------|--------|----------|
| D1   | spike通过, DB就绪 | 无 | RAG核心 |
```

## 4. 知识沉淀：NOTES.md（重点）

> **本项当前缺失，必须立即建立。**

从第一天起维护根目录 `NOTES.md`，记录：
- 哪些代码由 AI 生成、你**改了什么、为什么改**（面试官重点提问项）；
- 遇到的坑与解决（如 Chroma 版本 API 差异、SSE 缓冲导致假卡顿）；
- 对方案设计的偏离与理由。

示例：
```
## 2026-07-31
- llm_client.py 由 AI 生成，我将 base_url 改为 DashScope 兼容模式，
  因原生 OpenAI 地址在境内不可达。
- 前端 SSE 尚未实现，暂用 axios 占位（TODO）。
```

## 5. 评测与质量

- **评测集**：维护 25 条问答用例（覆盖产品/退换货/FAQ/边界问题），记录期望答案与检索来源。
- **质量门禁**：检索准确率 >80%、回答准确率 >75%、引用准确率 >90%、首字 <500ms。
- **回归**：每次 RAG 改动后跑评测集，对比上一轮分数。

## 6. 提交前检查清单（16 项）

1. `ruff check` / `npm run lint` 0 错误
2. `tsc` 无类型错误
3. 后端 `/docs` 所有接口可测通
4. 前端 SSE 用 fetch+ReadableStream（非 EventSource）
5. 响应头含 `X-Accel-Buffering: no`
6. 上传文档→Chroma 有向量→MySQL 有 chunk 记录
7. 删除文档后 MySQL 与 Chroma 同步清空（无孤儿向量）
8. 空检索走降级提示，不幻觉
9. 配额超限返回 429 且有提示
10. JWT 过期/无效返回 401 跳登录
11. 消息长度 >500 被拒
12. 引用 snippet 非空、可溯源
13. 8 份文档齐全且与代码一致
14. NOTES.md 已更新
15. `.env` 未入库，仅 `.env.example`
16. 邮件草稿（院校+姓名）待 Day5 23:59 发出
