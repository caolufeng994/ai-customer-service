# 业务流程说明

## 概述

本文档描述AI智能客服系统的核心业务流程，包括用户注册登录、知识库管理、智能问答等关键业务场景。

## 用户注册登录流程

### 注册流程

```mermaid
sequenceDiagram
    participant User
    participant Frontend
    participant API
    participant DB

    User->>Frontend: 输入手机号/邮箱和密码
    Frontend->>API: POST /api/auth/register
    API->>API: 验证参数（至少提供手机号或邮箱）
    API->>DB: 检查用户是否已存在
    alt 用户已存在
        API->>Frontend: 返回错误（手机号或邮箱已注册）
        Frontend->>User: 显示错误提示
    else 用户不存在
        API->>API: 生成随机salt
        API->>API: bcrypt加密密码
        API->>DB: 创建用户记录
        DB->>API: 返回用户ID
        API->>Frontend: 返回用户信息
        Frontend->>User: 注册成功，跳转登录
    end
```

**业务规则**：
- 手机号和邮箱至少提供一个
- 密码长度6-100字符
- 手机号和邮箱唯一性校验
- 密码使用bcrypt加密存储

---

### 登录流程

```mermaid
sequenceDiagram
    participant User
    participant Frontend
    participant API
    participant DB

    User->>Frontend: 输入手机号/邮箱和密码
    Frontend->>API: POST /api/auth/login
    API->>DB: 根据手机号或邮箱查询用户
    alt 用户不存在
        API->>Frontend: 返回错误（用户不存在）
        Frontend->>User: 显示错误提示
    else 用户存在
        API->>API: 验证密码（bcrypt）
        alt 密码错误
            API->>Frontend: 返回错误（密码错误）
            Frontend->>User: 显示错误提示
        else 密码正确
            API->>API: 生成JWT Token（24小时有效期）
            API->>Frontend: 返回Token和用户信息
            Frontend->>Frontend: 存储Token到localStorage
            Frontend->>User: 登录成功，跳转首页
        end
    end
```

**业务规则**：
- 支持手机号或邮箱登录
- JWT Token有效期24小时
- Token存储在localStorage
- 每次请求携带Token在Authorization头

## 知识库管理流程

### 文档上传流程

```mermaid
sequenceDiagram
    participant User
    participant Frontend
    participant API
    participant DB
    participant RAG

    User->>Frontend: 选择文件
    Frontend->>Frontend: 验证文件类型和大小
    alt 文件类型不支持
        Frontend->>User: 显示错误（仅支持txt/md/pdf/docx）
    else 文件大小超限
        Frontend->>User: 显示错误（最大10MB）
    else 验证通过
        Frontend->>API: POST /api/kb/documents (multipart/form-data)
        API->>DB: 创建文档记录（status=processing）
        API->>Frontend: 返回document_id
        Frontend->>User: 显示"处理中"状态
        API->>RAG: 异步后台任务
        RAG->>RAG: 保存文件到磁盘
        RAG->>RAG: DocumentLoader加载文本
        RAG->>RAG: TextSplitter分割文本
        RAG->>RAG: Embedder向量化
        RAG->>RAG: VectorStore存储向量
        RAG->>DB: 保存分块记录
        RAG->>DB: 更新文档状态（status=ready）
        alt 处理失败
            RAG->>DB: 更新文档状态（status=failed）
            RAG->>DB: 记录错误信息
        end
        Frontend->>API: 定期轮询文档状态
        API->>Frontend: 返回当前状态
        alt status=ready
            Frontend->>User: 显示"就绪"状态
        else status=failed
            Frontend->>User: 显示错误信息
        end
    end
```

**业务规则**：
- 支持格式：txt、md、pdf、docx
- 文件大小限制：10MB
- 异步后台处理
- 状态机：processing → ready/failed
- 文档删除时级联删除向量

### 文档删除流程

```mermaid
sequenceDiagram
    participant User
    participant Frontend
    participant API
    participant DB
    participant VectorStore
    participant Disk

    User->>Frontend: 点击删除按钮
    Frontend->>User: 确认删除
    User->>Frontend: 确认
    Frontend->>API: DELETE /api/kb/documents/{id}
    API->>DB: 更新文档状态（status=deleting）
    API->>DB: 查询所有分块记录
    API->>VectorStore: 批量删除向量
    VectorStore->>VectorStore: 从Chroma删除
    API->>DB: 删除分块记录（级联）
    API->>DB: 删除文档记录
    API->>Disk: 删除文件
    alt 删除失败
        API->>DB: 回滚状态（status=ready）
        API->>Frontend: 返回错误
        Frontend->>User: 显示错误提示
    else 删除成功
        API->>Frontend: 返回成功
        Frontend->>User: 刷新文档列表
    end
```

**业务规则**：
- 状态机保证一致性
- 先更新状态再执行删除
- MySQL和Chroma数据同步删除
- 失败时回滚状态

## 智能问答流程

### 单轮问答流程

```mermaid
sequenceDiagram
    participant User
    participant Frontend
    participant API
    participant DB
    participant RAG
    participant LLM

    User->>Frontend: 输入问题
    Frontend->>Frontend: 验证消息长度（≤500字符）
    alt 超长
        Frontend->>User: 显示错误（最多500字符）
    else 验证通过
        Frontend->>API: POST /api/chat/stream (SSE)
        API->>DB: 检查每日配额
        alt 配额超限
            API->>Frontend: 返回错误（每日100次限制）
            Frontend->>User: 显示配额超限提示
        else 配额充足
            API->>DB: 创建或获取会话
            API->>DB: 保存用户消息
            API->>Frontend: SSE推送session_id
            API->>RAG: 执行RAG检索
            RAG->>RAG: Embedder向量化问题
            RAG->>RAG: VectorStore相似度查询(阈值0.5)
            alt 检索结果非空
                RAG->>RAG: ContextBuilder构建上下文
                RAG->>RAG: PromptBuilder构建提示词
                RAG->>LLM: 流式生成回答
                loop 流式输出
                    LLM->>API: 返回内容片段
                    API->>Frontend: SSE推送content
                    Frontend->>User: 实时显示回答
                end
            else 检索结果为空
                RAG->>RAG: 直接走无上下文兜底提示
            end
            LLM->>API: 生成完成
            API->>DB: 保存助手消息
            API->>DB: 增加配额计数
            API->>DB: 更新会话消息数
            API->>Frontend: SSE推送done（含来源信息）
            Frontend->>User: 显示来源引用
        end
    end
```

**业务规则**：
- 消息长度限制：500字符
- 每日配额：100次提问
- **意图门控**：先经规则分类器判定意图——知识类意图（产品/价格/退款/账号/知识库/订单）走 RAG 主链路；兜底闲聊/越界意图走「直答」（不检索、不注入知识库）；空检索同样走无上下文兜底提示（固定话术，不调 LLM）
- 相似度阈值：0.5（不做阈值降级，检索为空直接走兜底提示）
- Top-K检索：8个结果
- **思维链流式**：RAG 链路在正式回答前经 SSE 推送 `thinking_start` → 若干 `thought` → `thinking_end`（基于真实检索上下文的实时推理），再推送 `content` 正文
- 流式响应提升体验
- 记录来源引用（回答中 `[K编号]` 与 `done.sources` 一一对应）

### 多轮对话流程

```mermaid
sequenceDiagram
    participant User
    participant Frontend
    participant API
    participant DB
    participant RAG
    participant LLM

    User->>Frontend: 发送第一个问题
    Frontend->>API: POST /api/chat/stream (session_id=null)
    API->>DB: 创建新会话
    API->>Frontend: SSE推送session_id
    API->>RAG: RAG检索（无历史）
    RAG->>LLM: 生成回答
    LLM->>Frontend: SSE推送回答
    Frontend->>User: 显示回答

    User->>Frontend: 发送第二个问题
    Frontend->>API: POST /api/chat/stream (session_id=1)
    API->>DB: 获取会话1
    API->>DB: 查询最近10条消息
    API->>RAG: RAG检索（带历史）
    RAG->>RAG: 将历史消息加入Prompt
    RAG->>LLM: 生成回答（理解上下文）
    LLM->>Frontend: SSE推送回答
    Frontend->>User: 显示回答
```

**业务规则**：
- 首次提问创建新会话
- 后续提问使用已有会话
- 保留最近5轮对话历史
- LLM理解上下文语境

## 反馈评价流程

```mermaid
sequenceDiagram
    participant User
    participant Frontend
    participant API
    participant DB

    User->>Frontend: 点击点赞/点踩
    alt 点踩
        Frontend->>User: 弹出原因选择（答非所问/事实错误/没召回/太啰嗦/其他）
        User->>Frontend: 选择原因（可选）+ 文字评论
    else 点赞
        Note over Frontend: reason 置为 NULL
    end
    Frontend->>API: POST /api/feedback (rating, reason?, comment?)
    API->>DB: 检查是否已评价
    alt 已评价
        API->>Frontend: 返回错误（已评价过）
        Frontend->>User: 显示错误提示
    else 未评价
        API->>DB: 创建反馈记录（含 reason/comment）
        DB->>API: 返回反馈ID
        API->>Frontend: 返回成功
        Frontend->>User: 更新评价状态
    end
```

**业务规则**：
- 每条消息只能评价一次
- 评分：1（点赞）、-1（点踩）
- 可选文字评论（最多500字符）
- 点踩时可选择结构化原因（reason）：答非所问 / 事实错误 / 没召回 / 太啰嗦 / 其他；点赞时 reason 为 NULL
- 管理员可通过管理后台（GET /api/admin/feedbacks）查看全量反馈，并支持按评分、原因、关键词、时间区间筛选

### 管理员反馈分析与优化飞轮

```mermaid
flowchart LR
    A[用户提交反馈<br/>rating + reason + comment] --> B[管理后台集中展示<br/>GET /api/admin/feedbacks]
    B --> C[按原因聚类<br/>答非所问/事实错误/没召回...]
    C --> D[定位失败 Case<br/>关联消息与知识库]
    D --> E[优化 RAG / Prompt / 知识库]
    E --> F[将高频失败问题<br/>回流评测集]
    F --> A
```

- 反馈数据经 `messages` 间接关联到 `sessions` 与用户账户（`email` 或 `phone`），管理员可见「用户 / 会话标题 / 关联消息内容」。
- 管理后台提供统计概览接口（`GET /api/admin/feedbacks/summary`）：总反馈数、点赞/点踩数、按原因分布，用于快速识别集中问题。
- 高频「没召回 / 事实错误」类反馈可转化为评测集用例，形成「收集 → 分析 → 优化 → 回流」的持续迭代闭环。

## 异常处理流程

### 配额超限处理

```mermaid
flowchart TD
    A[用户提问] --> B{检查配额}
    B -->|配额充足| C[继续处理]
    B -->|配额超限| D[返回错误]
    D --> E[前端显示提示]
    E --> F[建议明日再试或联系客服]
```

### 知识库空检索处理

```mermaid
flowchart TD
    A[检索知识库] --> B{检索结果}
    B -->|有结果| C[构建上下文]
    B -->|无结果| E[使用降级提示]
    E --> F[告知用户无法回答]
```

### LLM调用失败处理

```mermaid
flowchart TD
    A[调用LLM] --> B{调用成功}
    B -->|成功| C[流式返回]
    B -->|失败| F[返回错误]
    F --> H[前端显示错误提示]
```

## 数据流转

### 文档上传数据流

```
用户文件 → API接收 → 磁盘存储 → 文本提取 → 文本分割 → 向量化 → Chroma存储 → MySQL记录
```

### 问答数据流

```
用户问题 → 向量化 → Chroma检索 → 结果过滤 → 上下文构建 → 提示构建 → LLM生成 → 流式返回 → MySQL存储
```

## 关键指标

### 性能指标
- 首字输出时间：<500ms
- 平均响应时间：<2s
- 文档处理时间：<3min（10MB文档）

### 质量指标
- 检索准确率：>80%
- 回答准确率：>75%
- 引用准确率：>90%

### 业务指标
- 日均提问量：100次/用户
- 文档处理成功率：>95%
- 用户满意度：>85%
