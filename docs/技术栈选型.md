# 技术栈选型

本文档记录关键技术组件的选型理由，说明"为什么选它、为什么不选备选"，便于评审理解工程权衡。

## 1. 后端框架：FastAPI（备选 Flask / Django）

- **选型理由**：原生 `async/await`，天然支持 `StreamingResponse` 做 SSE 流式输出；基于 Pydantic 的自动参数校验与类型提示；自动生成 OpenAPI/Swagger（`/docs`），减少接口文档维护成本；性能好（Starlette/uvicorn）。
- **不选 Flask**：同步模型，流式需额外封装；无内置校验。
- **不选 Django**：过重，ORM 与本项目轻量需求不匹配，启动慢。

## 2. 关系数据库：MySQL 8.0 + SQLAlchemy 2.0（备选 PostgreSQL）

- **选型理由**：关系模型清晰（用户/会话/消息/知识库/引用/配额），事务保证文档删除的原子性；MySQL 通用、面试友好、本地易起。向量由 Chroma 存，MySQL 只存元数据与正文，职责分离。
- **SQLAlchemy 2.0**：类型安全 ORM，避免裸 SQL 注入风险。

## 3. 向量数据库：Chroma 0.4.22（备选 Milvus / Qdrant / FAISS）

- **选型理由**：**零运维、本地文件持久化**（`PersistentClient`），单机即可跑通完整 RAG 链路，最适合 5 天单人笔试。支持 `where` 元数据过滤（按 `kb_id` 隔离知识库）、`delete_by_ids`（配合 `vector_id` 做级联删除）。
- **不选 Milvus**：分布式，部署重，单人场景杀鸡用牛刀。
- **不选 FAISS**：纯内存索引，无持久化与元数据过滤，删除管理复杂。
- **备选 Qdrant**：若需更高并发再迁移，接口可封装替换。

## 4. LLM：DashScope qwen-plus（通义千问，云端）

- **选型理由**：国内网络稳定可达，且**兼容 OpenAI SDK**（`base_url` 切换即可），代码无需为厂商改写；成本低于 GPT-4 类；支持流式。
- **降级链路**：当前仅使用云端 DashScope，未实现本地降级（原 `fallback_to_ollama` 路径已移除）；LLM 调用异常时统一返回错误，由前端提示重试。

## 5. Embedding：DashScope text-embedding-v3（1024 维，云端）

- **选型理由**：中文语义质量高，与 qwen 同生态；维度 1024 兼顾精度与存储。
- **备选**：无（当前仅支持 DashScope；`Embedder` 抽象层保留可扩展，但本地方案未实现）。

## 6. 认证与安全：JWT（python-jose）+ bcrypt（passlib）

- **选型理由**：无状态 Token，前端存 localStorage 每次请求携带；bcrypt + 随机 salt 防彩虹表；与 `core/exception_handlers` 统一鉴权失败响应。

## 7. 前端：React 18 + Vite + TypeScript + Ant Design（备选 Vue / Tailwind）

- **选型理由**：React 生态广、Hooks 心智简单；Vite 启动快、HMR 体验好；TS 类型安全减少联调错误；Ant Design 组件全，可快速搭出合规 UI，**默认样式即满足笔试"界面整洁"要求，无需自写大量 CSS**。
- **SSE 客户端选型（关键）**：**必须用 `fetch` + `ReadableStream` 手动解析 `text/event-stream`**，绝不能依赖 `EventSource`——因为流式接口需要 `POST` 方法并携带 `Authorization` 头，而 `EventSource` 只支持 GET 且无法自定义请求头。这是本项目的明确技术约束，前端实现必须遵循（**当前前端尚未实现 SSE，是最高优先级待办**）。

## 8. 选型总原则

单人、5 天、可本地运行、可演示 > 工业级伸缩。所有选型优先"零运维、易跑通、易讲解"，并在抽象层（LLMClient / Embedder / VectorStore）预留切换接口，便于在面试中展示扩展思路。
