## 一、功能需求

### 1.1 用户与会话模块
| 功能点 | 结论 | 说明 |
|---|---|---|
| 注册/登录（手机号+密码 或 邮箱+密码） | ⚠️ 需核实 | 模型层 `user.py` 含 phone/email 字段，文档称"支持两种登录"，但登录接口是否同时接受两种标识符需实测确认（未读到 auth 路由的账号解析逻辑）。 |
| 发起独立 Session 对话 | ✅ | `session.py` / `chat_service.create_session_if_needed` 支持。 |
| 历史会话列表 + 会话详情（完整对话记录） | ✅ | `session.py` 提供列表与详情接口。 |
| 对回答反馈（点赞/踩 + 可选文字） | ✅ | `feedback.py` + `feedbacks` 表（含 rating + comment）。 |

### 1.2 核心 AI 对话模块
| 功能点 | 结论 | 说明 |
|---|---|---|
| 上传 .txt/.md/.pdf 并自动解析向量化 | ✅ | `loader.py` 支持三格式（PyMuPDF 解析 PDF），`vector_store.py` 落 Chroma。 |
| 知识库列表（名称/上传时间/状态：处理中/就绪/失败） | ✅ | `knowledge_service.py` 状态机：`processing→ready/failed`，`deleting` 失败时回滚 `ready`。 |
| 删除文档后向量同步清除 | ✅ | `kb_chunks.vector_id` 作为 MySQL↔Chroma 桥梁，删除时按 vector_id 批量删向量（前期审计已验证）。 |
| RAG 全链路（提问→检索→拼 Prompt→LLM→流式） | ✅ | `chat_service.chat_stream` 完整编排。 |
| 回答展示引用来源（文档名 + 片段摘要） | ✅ | `citations` 含 `doc_id/chunk_id/score/snippet`（120 字截断）。 |
| 多轮对话（最近 N 轮上下文） | ✅（实现口径为"条"） | `get_conversation_history(limit=10)` = 最近 10 条消息≈5 轮；题目要求"N 轮"，此处按条数实现，效果等价但命名不严谨。 |
| 单次提问 ≤ 500 字 | ✅ | `ChatRequest.max_length=500` + `chat_service` 二次校验。 |
| 检索不到返回兜底话术、不编造 | ✅ | `retrieve_with_fallback`（0.6→0.3）+ `build_fallback_prompt`。 |
| 每日提问上限 100 次（可配置） | ✅ | `usage_quota` 表 + `check_quota/increment_quota` + `DAILY_QUOTA_LIMIT=100` + `QuotaExceededError`。 |
| 流式逐字输出（SSE） | ✅ | 后端 SSE + 前端 `fetch+ReadableStream` 已修复（R1 已闭环）。 |

## 二、技术栈要求

| 要求 | 结论 | 说明 |

| 前端 React+TypeScript（或 Vue3） | ✅ | React 18 + TS + Vite + AntD。 |

| LLM：OpenAI / 通义千问 / Ollama 任选 | ✅ | DashScope 通义千问（已升级 `qwen3.7-plus`），Ollama 降级备用。文档已说明。 |

| 前后端分离 + RESTful | ✅ | `/api/*` 路由分组，REST 风格。 |

| 流式用 SSE 或 WebSocket | ✅ | SSE（含 `X-Accel-Buffering: no` 抗缓冲）。 |

## 六、总体结论

**必须项完成度高**：核心功能、技术栈、评估四维度、提交目录结构与安全规范（.env 隔离）均达标，RAG 全链路与流式体验经实测修复后可用。

**主要失分风险集中在"文档规范"**：① 3 个文档文件名与题目要求不一致（最易被阅卷脚本直接判缺）；② `项目说明.md` 强制要求的"业务思考 / AI 工具使用体会 / AI 代码修正 / 质量验证"四节基本缺失；③ 两道重点加分题的设计仅停留在规划文档，未进入交付文档；④ 种子知识库未自动向量化，影响"启动即可测问答"。

**建议按 G1→G2→G3→G4→G5 顺序处理**，其中 G1/G2/G3/G4 是离"符合题目字面要求"最近、收益最高的动作。
